# CLAUDE.md

[`README.md`](README.md) describes the project. This file holds what an agent needs on top of it.

## Language

- **Everything in the repository is in English**: code, identifiers, comments, file names, the database schema, commits, branches, PR titles and descriptions.
- Player-facing text exists in English and French, and only in translation files, never inline.
- Talk to the user in French.

## Rules that protect the project

- **Never commit card data or card images**, nor any other third-party asset whose license allows no redistribution. They are imported at runtime or deploy time from outside the repository. The repository runs on placeholder cards.
- **Keep the product name, domain, logos and repository metadata generic**, without third-party trademarks.
  - **Temporary exception, decided by the owner**: the card back in `components/game/boosters/card-back.tsx`, used when opening boosters and in Papy Caillou's memory game, imitates the real cards' back. The owner allows it for now, knowing the consequences, and it is to be replaced by a back of our own later. Don't add other third-party designs on the strength of it.
- **The server decides.** Booster draws, balances, duplicate coins and quest rewards are computed on the server, never trusted from the browser. The browser only displays the result. Coins, boosters and the collection live in the database and only change through the modules of `player/`.
- **Statistics only in aggregate.** The game's statistics count and add up across players, and never show a player's name, email or anything that points to one player.
- **No real money**: no payments, donations or ads.
- **Single-player only.**

## Git workflow

Work reaches `main` through a squashed PR, never a direct push. Lefthook refuses a push from `main`, and GitHub refuses force-pushing or deleting it.

- **Branches**: `<type>/<topic>`, such as `feat/booster-opening`.
- **Commits and PR titles**: Conventional Commits, `type(scope): subject`.
- **Types**: `feat`, `fix`, `perf`, `docs`, `refactor`, `revert`, `chore`, `build`, `ci`, `style`, `test`, plus `balance` (numbers change, no new mechanic) and `content` (cards, sets, NPCs or text added, no new system).
- **Scopes** name systems, not files: `city`, `shop`, `boosters`, `binder`, `quests`, `npc`, `cards`, `accounts`, `db`, `i18n`, `deps`.
- **`/open-pr`** runs the gate, pushes, writes the description and turns on Auto-fix. **`/sync`** cleans up once the user says a PR is merged.
- **Commit or push only when asked.** Merging is always the user's call.
- **Never write a CI-exclusion marker** in a commit message or PR text. GitHub Actions obeys it anywhere in the message, which skips the release.
- **Do not edit `CHANGELOG.md` or the version by hand.** Every merge to `main` makes the `release` job in `.github/workflows/ci.yml` bump the version, regenerate the changelog, tag `vX.Y.Z` and publish a GitHub Release.

## Data

The schema lives in `db/schema`, and every change goes through a migration in `db/migrations`. Call `getDb()` from `db/client.ts` on the server only. Add a table with the feature that needs it.

Production runs the `Dockerfile` and never migrates on its own: a migration is applied by hand with the owner's address, as the README's "Deploying" section shows, before the merge for an additive one and after the deploy for a destructive one. The game connects as `tcg_app`, from `db/prod-runtime-role.sql`, which only reads and writes rows; tables created later get its rights by default. A file read at runtime through a path the build can't follow, like the fonts in `components/brand/assets.ts`, goes in `outputFileTracingIncludes` in `next.config.ts`, or the standalone server won't have it.

`game_events` is the game's event log, only ever added to. Every action that changes a player's coins, boosters, collection or quests records its event with `recordEvent` from `player/events.ts`, in the same transaction, so that an event exists exactly when its action does. Signing up and in are recorded too, from `auth/server.ts`, and so is each arrival in another place, through a door or by bus, when the spot saved changes place. Each opening of the game's page is a visit, `game.opened`, with its language, the kind of device and only the domain the link came from, kept from the tab's first page by `components/landing-referrer.tsx` since a shared link usually lands on the sign-in page first. Leaving the page sends `game.left`, timed by the server from the opening, by `recordVisitEnd` in `player/visits.ts`. A visit gives no advantage, so it is checked for its shape only, by `parseVisit` in `game/log/visits.ts`. The browser also reports how players play, through `reportPlay` in `components/game/report.ts`: each conversation, `npc.talked`, each seller's shop window looked through, `shop.viewed`, each binder opened, `binder.viewed`, and each booster taken out of the bag then put back before being cut, `booster.abandoned`. `parseReport` in `game/log/reports.ts` checks them against the game's own names. Going to bed records `player.slept`, from the server. Every event that changes a player's coins also carries `coinsAfter`, their coins once it is done, read by `coinsNow` in `player/wallet.ts` in the same transaction, so that the reports can tell how rich players are over time. The catalogue of types and their details is in `game/log/events.ts`. It is a contract with whatever reads the log, the game's statistics now and tools of their own later: a type's name and its details' fields never change once recorded, a new need gets a new field or a new type, and details hold no personal data. A new action gets its type in the catalogue, and a test fails for any type that nothing records.

`player_cards` deliberately has no foreign key to `cards`, because `pnpm cards:import` replaces a set's card rows.

`player_spots` keeps where the character stands, its place, how far along the floor and which way it faces, saved from the browser at each change of place and when the page is left, and checked by `parseSpot` in `game/world/spot.ts`. A spot gives no advantage, so it isn't checked for how the player got there. A spot that a change of the places has made invalid is ignored, and the player starts in the bedroom.

## Cards

The card catalogue comes from [TCGdex](https://tcgdex.dev/) and only lives in the database, never in the repository. Tests use placeholder data. `pnpm cards:import` copies a set in one transaction and can run again safely. Card images stay hosted by TCGdex. So do set logos, which TCGdex has as PNG, WebP or both: `logoFiles` in `cards/tcgdex.ts` lists them in the order to try, for the game and for the import alike.

The game plays with the sets in `game/cards/card-sets.ts` that have been imported, and every one of them is on sale. Mamie Noisette sells every binder. The raccoon triplets of the Card Den share the boosters through `setsSoldBy` in `game/cards/shop-dialogue.ts`: Filou, the eldest, has the 30th anniversary and the Mega Evolution sets under the sign Méga Merveilles; the rest is split by age, the older half to Frimousse, the middle one, at Trésors d'Antan, and the newer half to Fripouille, the youngest, at Bonnes Pioches. Their stock ids, `latest`, `thisYear` and `older`, are those of an earlier split, kept because the event log records them. A player can only buy a set's boosters after buying its binder from Mamie Noisette, the hedgehog who keeps the bookshop, and the binder list only shows the binders they bought. Talking to a seller offers to open her shop window, `components/game/shop/shop-window.tsx`: every item in a grid, and the chosen one's details with the button to buy it. Enter or Space on a binder buys it at once where the grid and the details stand side by side, as on a desktop, and the keyboard stays in the grid for the next one; on a phone, it opens the details. On a booster, the same keys go to the quantity field, where Enter buys and sends the keyboard back to the grid. Boosters can be bought several at a time, up to `MAX_BOOSTER_QUANTITY` in `game/cards/shop-dialogue.ts`, paid for and added in one transaction. `components/game/shop/quantity-picker.tsx` picks how many: ×5, ×10, ×20 or the most the coins pay for in one touch, a number to type, and step buttons that repeat while held. A click on a step button counts once through its own click, whatever the browser, and only a press held long enough repeats. A set without its own recipe in `game/cards/booster.ts` gets one built from its rarities, and a set without its own pack theme in `components/game/boosters/pack-art.tsx` takes the colour of its logo from `game/cards/set-colors.ts`.

Every booster holds ten cards, without energy or code bonus cards. A recipe adapts the slots to its set's rarities, and every version of every card must stay obtainable: `pnpm cards:import` warns about any that aren't. Cards are revealed from the most common to the best, following the recipe's `revealOrder`. A player with five or ten boosters of a set in the bag can also open them as a lot, from `BOOSTER_LOT_SIZES` in `game/cards/booster-lots.ts`: one cut opens the whole lot, `openOwnedBoosters` in `player/shop.ts` takes it from the bag and opens each booster in turn in one transaction, recording a `booster.opened` for each as if opened one by one, and once the pack's light effects have climbed to the lot's best card the opening skips the reveal card by card for a summary of every card, the best and the new ones first. As the game's own rule for every set, one booster in two thousand is instead a god pack of ten hits, which the opening only announces once the pack is cut.

Opening a booster also needs its set's binder. Boosters won from quests or coupons wait in the bag, `components/game/boosters/booster-bag.tsx`, greyed out with a tag, until the binder is bought, and `openOwnedBoosters` in `player/shop.ts` refuses them with `needsBinder`.

The server only takes the booster and draws the cards when the pack is cut. Until then the player can back out at no cost, and backing out can't be used to draw again. A cut sends a single request: the pack locks itself with a ref at the first tear, since a finger sends several moves before React draws again, and `cutBooster` in `components/game/boosters/use-booster-opening.ts` lets only one request be on its way. Without both, one gesture opened several boosters.

Opening a booster pays for its duplicates in the same transaction, from the values in `game/cards/duplicate-coins.ts`. A duplicate is a version of a card the player already owns. The copy is kept, so that the binder still counts it.

Special versions catch the light, by `cardFoil` in `game/cards/foil.ts`, drawn by `components/game/boosters/card-foil.tsx`: as on the real cards, a holo's rainbow foil with glitter covers only its illustration's window and a reverse's covers everything but it, the other special versions getting a passing shine. `TiltCard` moves the foil's light with the pointer; at rest, and on small cards, it drifts by itself, still for players who ask for less motion.

Once cut, the pack climbs through light effects up to its best card, from a `PullTier` in `game/cards/pull-tier.ts`. The server gives each card its tier from the rarity in English. A new rarity needs a tier there, or it gets the plain opening.

A card's `rarity` column is in English, because game rules compare it. Translated rarities are for display only.

## Quests

Twenty quests are daily. Each one's rules live in its own file under `game/`, and every reward is paid on the server in `player/quests/`, a file per quest or family of quests, beside `attempts.ts`, which starts and finishes the attempts they all share. A quest pays once a day, by UTC date, so that it can't be repeated for endless coins; the shifts below pay each new star of the day instead, up to their last. Its row in `player_quests` keeps when an attempt started and the day it was last done.

Léa's quest is in `game/quests/quests.ts`, with the timing rules the others share. Léa, the overworked rabbit next door, asks Pip to dust the walls of her flat: each patch of dust takes a few rubs with the interact key. The dusting happens in the browser, so the server records when an attempt starts and only pays if the time adds up. Her quest keeps the id and giver it had as the grandmother's (`grandma-cleaning`, `grandma`), because players' progress is stored under them. Until her walls are dusted for the day, Léa breathes fast and sweats.

Papy Caillou's memory game is in `game/quests/memory-game.ts`. He is the old tortoise of the park, and his quest keeps the id it had as the grandfather's. Its board stays in `player_quests.memory_game`, and each flipped card is a request to the server, which alone counts the moves and pays. The game's pictures go to the browser at the start, without their positions.

Lucas's fishing quest is in `game/quests/fishing.ts`, at the park's lake. Lucas is a little otter who keeps dropping his things in the water, and the player fishes them out. The server draws what comes up when it is reeled in, in the transaction that uses up the attempt, so backing out can't be used to draw again. His everyday things pay coins, and his treasure box, one time in five, pays a booster of the newest set. The wait for a bite is only for show. The things are simple drawings of our own.

Gaspard's dalgona is in `game/quests/dalgona.ts`. He is a slim, sly fox with a stand out in the street, between our house and the shop. The player carves a shape out of a caramel biscuit by holding a key or the button: the needle follows the outline while held, and the pressure builds, faster in the corners, until letting go eases it or the biscuit breaks. The server picks the shape from the moment the game starts, so that it needn't be stored, and pays by the shape. The browser only sends when each press started and ended, and the server replays them step by step with the same rules, after checking that the game took as long as its presses. A broken biscuit can be tried again, until one carved whole pays for the day. The game's clock starts once, when its dialog opens: the game page draws again whenever the time of day or the weather changes, so `DalgonaDialog` reads `onFinish` through a ref rather than restarting on it, which froze the biscuit mid-game.

Bérénice's raffle is in `game/quests/raffle.ts`. She is a jolly goat with a stand out in the street, between the bookshop and the arcade, balloons tied to its posts. The player turns the drum's crank once a day for free: the server draws the ball and pays in the same transaction that uses up the day's turn, 3,000 coins for the golden ball three times in a hundred and 300 for a red one ten times in a hundred, and nothing otherwise. Nothing is drawn until the crank is turned.

The arcade's basketball machine is in `game/quests/basketball.ts`. The browser only sends when each shot left, and the server replays them with the same rules to get the score, after checking that the game lasted its full time. It can always be played, and `player_high_scores` keeps the best score, but only one game a day pays: the first to earn a reward. A game that earns nothing leaves it to be won. The other machines are decoration.

The big city's shifts share `game/quests/shifts/shifts.ts`: their quest ids, their rules and pay, and the replay of their presses. Yuzu is a red panda who runs Ramen Yuzu, a low wooden house between the big city's towers, and hires the player for three jobs, each its own daily quest and its own little game, simulated from a seed and the presses so that the browser draws exactly what the server plays again. Washing up, in `game/quests/shifts/ramen-dishes.ts`: dirty bowls pile into a tub that overflows when left, each bowl is scrubbed once per stain, by a button or by rubbing it, rinsed and stacked, and the pile, ever shakier, scores once carried to Yuzu, with a bonus that grows with its height and a chance that it topples. Helping in the kitchen, in `game/quests/shifts/ramen-kitchen.ts`: bowls ride a belt under six bins, and each one's ingredients go in, in any order, before it leaves the zone, the belt going faster. Waiting tables, in `game/quests/shifts/ramen-service.ts`: the village's folk queue at the door, sit at four tables, order a bowl that comes out of the kitchen onto the pass, eat, and leave their table to clear; touching a table clears it or brings it the bowl in hand. Wrong moves, an overflowing tub, a fallen bowl or an angry guest are mistakes, three end the shift, quick work earns bonuses, and the shift ends in one to three stars from `shiftStars`. `components/game/shifts/shift.tsx` holds what every shift's scene shares, from starting a shift on the server to counting it, with an optional guide of pages the player can leaf through before starting, as Papy Caillou's stones have, sent as soon as the shift ends while the board stays frozen on the last move until the player asks to see the score, the clock giving way to "Finished!" and the host's closing words laid over the board, since a stopped clock and a "next…" label once made shifts that end before their time look stuck, `ramen-dishes-scene.tsx`, `ramen-kitchen-scene.tsx` and `ramen-service-scene.tsx` draw Yuzu's, with her commenting, and `components/game/shifts/shift-dialog.tsx` holds the conversation of whoever offers the shifts. The server sends a shift's seed, the moment it started, when the player presses start after reading how to play, refuses presses closer than a person could make, presses that do nothing, and presses after the shift ended, and checks that the shift lasted as long as it played. It pays coins by score, star by star as the next paragraph tells, and every finished shift records its stars in `quest.finished`, so that Mme Hulotte's reports show how often each job's stars are reached; quests from now on pay coins, never boosters.

Maître Kaito's dojo stands next to Ramen Yuzu, white plaster and dark timber under a sweeping roof. Kaito is an old badger in a white gi, and his two lessons are shifts like Yuzu's jobs, each its own daily quest. Slicing, in `game/quests/shifts/dojo-slicing.ts`: vegetables are thrown up in four lanes and fall back, no more than two in a lane at once, and a stroke cuts the throws it names, never the others in their lanes: a press holds two bits a lane, for the first and the second throw in the air there. The mouse or a finger has to move the blade through a throw to cut it, those touched quicker than a press can follow together, and a key or a lane button cuts the one thrown first in its lane. A cut at the top of the flight is clean, several at once a combo, and cutting a clay pot or letting a vegetable land are mistakes; a pot never shares a lane with a vegetable in flight, so that a key never breaks one by surprise. Archery, in `game/quests/shifts/dojo-archery.ts`, out in the dojo's garden, which the back screens open onto: ten arrows, each aimed in two presses, the first holding a line that sweeps from side to side and the second holding a line that sweeps up and down and loosing the arrow where they cross, the lines sweeping faster arrow after arrow; a wind per arrow carries it sideways, so the first line is best held into the wind. Rings score, and bullseyes in a row earn a bonus. `components/game/shifts/dojo-slicing-scene.tsx` and `dojo-archery-scene.tsx` draw them, with Kaito commenting. Linden Park has three more shifts. Pépin, a squirrel gardener in a straw hat, tends a garden at the park's far left, with a fountain, five flower beds and three sorting bins, and offers two chores. The clean-up, in `game/quests/shifts/park-cleanup.ts`: the player walks along the park's path pulling a cart with three bins, paper, packaging and glass, and litter comes their way, quicker as the shift goes on; when a piece is within reach, the keys 1 to 3 or the bins sort it, the wrong bin or a piece left behind being mistakes and five good sorts in a row a bonus. Watering, in `game/quests/park-watering.ts`, is not a shift but a gentle chore like Léa's dusting, offered by an extra button of Pépin's conversation: five thirsty beds, each blooming after three pourings by a click or the keys 1 to 5, with no clock and no mistake; `components/game/quests/watering-dialog.tsx` plays it, and the server records when it started and pays a fixed 150 coins once a day if the time adds up. Papy Caillou, once a stone-skipping champion, offers the skipping stones next to his memory game, through an extra button of his conversation: in `game/quests/shifts/park-stones.ts`, five pebbles each thrown in two presses, an angle swept by a needle, then a strength swept by a gauge, the skips counted from how close both are to the right throw: low and flat, as on a real lake, about 20 degrees without wind, the angle physicists measured as the best, which the lake's wind moves by up to 9 degrees as the reeds and the dial's guide line show, and the strength in the middle of the green band. `components/game/shifts/park-cleanup-scene.tsx` and `park-stones-scene.tsx` draw the clean-up and the stones.

The village has three more quests. Mamie Noisette's quiz, in `game/quests/quiz.ts`, is a calm chore offered by an extra button of her shop's conversation: five questions about the village and its folk, three answers each, drawn with the order of their answers from the moment it began, so that the browser never learns which is right; `components/game/quests/quiz-dialog.tsx` asks them, and the server scores the answers and pays 30 coins a right one, once a day. Bérénice's Pop'Balloons, in `game/quests/shifts/raffle-balloons.ts`, is a shift opened straight from an extra button of her conversation: balloons of four colours rise in four lanes, she calls a colour that changes every few seconds, and a key or a lane's button pops the highest balloon of its lane while a click or a touch pops the balloon it lands on, the called colour scoring and any other a mistake. Gustave, a heron postman, keeps a post stand between the shop and the bookshop and offers the mail, in `game/quests/shifts/post-mail.ts`: letters reach his counter one at a time, each filed in the pigeonhole of its stamp, an express letter scoring double when quick and a parcel taking two presses, the wrong pigeonhole or a letter slipping off the counter being mistakes. `components/game/shifts/raffle-balloons-scene.tsx` and `post-mail-scene.tsx` draw them.

Three more quests spread across the places. Pinceau, a sheep who paints the park's lake at his easel, between Papy Caillou and the water, has his painting put back together, in `game/quests/painter-puzzle.ts`: a 3×3 sliding puzzle mixed from the moment it began by random slides from the finished painting, so that it can always be solved; pieces slide by a click or the arrow keys, each pushing the piece beyond the gap, and the browser sends the moves, which the server plays again before paying 150 coins once a day, 250 in 40 moves or fewer. `components/game/quests/puzzle-dialog.tsx` plays it, and the painting is drawn by `drawPainting` in `components/game/art/painter.ts`. Mme Ronron, an old cat waiting on the pavement left of Léa's block, has lost her kitten Mistigri, in `game/quests/lost-kitten.ts`: talking to her gives a hint of the day's hiding place, one of the `HIDING_SPOTS` in `game/world/side-rooms.ts`, crates, bushes, flowers or a log drawn in the village, the park or downtown. The hiding place is drawn on the server from the player and the date, a search with the interact key at one of them is a request, recorded as `kitten.searched`, and only the right one, the same day as the hint, pays 200 coins, once a day, its `quest.finished` scoring the day's searches; `PlayerProgress.isKittenHunted` lets the hiding places be searched after a reload. Flash, a chameleon photographer on the big city's pavement, offers a shift, in `game/quests/shifts/city-photos.ts`: hot-air balloons and kites cross the camera's viewfinder, and a roll of eight shots scores by how close to the centre each subject is, kites more than balloons, a shot of an empty sky being a mistake; `components/game/shifts/city-photos-scene.tsx` draws it. Every shift, Yuzu's jobs and Kaito's lessons alike, can be replayed all day for a better score: each new star of the day pays the difference in coins, 120 for one star, 200 for two and 300 for three, by `shiftPayout` in `game/quests/shifts/shifts.ts`, `player_quests.paid_coins` keeping what the day has paid; once the three stars are paid, the shift and its host say that every reward of the day is earned. The third star is meant to be hard but not to ask for a perfect game: `game/quests/shifts/shifts-stars.test.ts` plays every shift as a good but imperfect player, reading the screen every 0.6 seconds and missing timings by about 40 milliseconds, and fails if that player reaches three stars in fewer than 30% of games. A new shift, or a change of its rules or pay, must keep it passing.

The activity tracker, under the settings button, opens `components/game/hud/activity-dialog.tsx`, whose first tab lists the day's quests from `game/quests/activity.ts`. A quest counts as done once it is used up for the day, its `completed_on` set to today: paid for most, drawn for the raffle, won or not. Doing any six of them earns a daily bonus of 600 coins, so that nobody has to play every quest: the player claims it with a button, and the server pays it once a day under its own quest row, `daily-bonus`, after counting the quests done. The others are extra, and the counts stop at six. The game reads the day's activity again whenever a dialog closes.

## Accounts

Playing requires an account: pages and API routes check `getPlayer()` from `auth/session.ts` on the server. [Better Auth](https://www.better-auth.com/) handles sign-up, sign-in, sessions and password hashing through `auth/server.ts`. Only the email, username and hashed password are collected. Show players `auth/rules.ts` error keys, never the library's messages. In `components/auth/fields.tsx`, every password field has an eye that shows what was typed, and signing up asks for the password twice, warning as soon as the second strays from the first.

A forgotten password is reset by email, in `auth/password-reset.ts`. The sign-in page links to `forgot-password`, whose answer is the same whether the address has an account or not, and the email leaves without being awaited so that the answer's time doesn't tell either. The email, in the language of the page it was asked from, links to `reset-password?token=…`, which checks the token before showing its form. A link lives 15 minutes and works once, tokens are stored hashed, an account gets at most three emails an hour, since Better Auth's own rate limit counts by IP address, which the game doesn't keep, and a reset signs the account out everywhere and records `player.password_reset`. `email/` sends emails through Scaleway Transactional Email once `SCALEWAY_SECRET_KEY`, `SCALEWAY_PROJECT_ID` and `EMAIL_FROM` are set, and prints them in the server's output otherwise; in production, never the link, and `canSendEmail()` hides the reset until the variables are set. Every email shares the look of `email/layout.ts`, tables and inline styles being all that mail apps draw: the banner `/email-header.png`, which the game draws with its own font since mail apps can't load it, then a scrap of paper on kraft, and the link written out under the button.

An admin is a player with a row in `player_roles`, set by hand in the database, for instance `insert into player_roles (user_id, role) select id, 'admin' from users where name = '<username>';`. `isAdmin()` in `auth/roles.ts` reads it on the server. The administrative office in the big city has no door to walk through: the way in is to talk to Brutus, the bulldog who guards it, who asks admins which floor they are going to and tells anyone else that it is for staff only. He is only a picture of the rule, so everything in the bureau that matters checks `isAdmin()` on the server again, and a spot in the bureau is neither saved nor restored for anyone else. Inside, Mme Hulotte, an owl, keeps the bureau and opens her reports on her computer, `components/game/office/stats-dialog.tsx`, drawn as a dark dashboard on a monitor rather than paper: the game's statistics for today, the last seven or thirty days, or since the start, on its economy, boosters, quests and players, charted over the period by the hour, day or week from `statsBuckets` in `game/log/stats.ts`, the event log's coverage, where a type never recorded stands out, and the draws card by card, from `components/game/office/stats-cards.tsx`: every binder with its logo, then a binder's cards with how often each version came out per booster since the start, or that it never did. Each `booster.opened` event records its ten cards for this, from November 2026 on; `loadSetDrops` in `stats/card-stats.ts` counts them, and `GET /api/stats/cards` checks `isAdmin()` too. The charts in `components/game/office/stats-charts.tsx` keep one axis, show a step's values on hover, and carry the same figures in a table for screen readers. `loadGameStats` in `stats/game-stats.ts` works them out from `game_events` with aggregate queries, and `GET /api/stats` checks `isAdmin()` before sending them. Only aggregates leave that module. Beside her, Bastien, a beaver archivist, hands over the full card statistics as a CSV file, from `GET /api/stats/cards/export`, which checks `isAdmin()` too: every version of every imported set, how many times it came out of the boosters that recorded their cards, and how many times per booster its recipe says it should, from `expectedPulls` in `game/cards/booster.ts`, so that the draws in production can be checked against the recipes. `loadCardStatsRows` in `stats/card-stats.ts` gathers them and `cardStatsCsv` in `game/cards/card-stats.ts` writes them.

The office has floors and a lift rather than doors: Brutus asks admins which floor they are going to, and the lift, in the left wall of each floor where a door would be, opens `components/game/office/elevator-panel.tsx`, a button for each of `OFFICE_FLOORS` in `game/world/side-rooms.ts`, the street, the office and the coupon floor, and one to stay. The coupon floor, the place `coupons`, is admins only like the office, whose spot `ADMIN_PLACES` keeps for admins alone. Mlle Trotte, a mouse, keeps it and opens her register, `components/game/office/coupon-register.tsx`: every coupon made, with how many players used it, and a form to stamp a new one, its code typed or generated, giving coins, boosters of a set, or both, and an optional expiry day. A coupon can be deactivated from its line in the register, and reactivated: it is kept with its uses, `deactivated_at` set, and `redeemCoupon` refuses it as no longer valid; `PATCH /api/admin/coupons` checks `isAdmin()` and `setCouponActive` in `coupons/admin.ts` records `coupon.deactivated` or `coupon.reactivated`. `parseCouponDraft` in `game/cards/coupons.ts` checks the form, and `GET` and `POST /api/admin/coupons` check `isAdmin()`; `coupons/admin.ts` keeps the register and records `coupon.created`. Any player uses a coupon once, by typing its code in the settings: `redeemCoupon` in `player/coupons.ts` checks it and pays it in one transaction, its row in `coupon_redemptions` making a second use impossible, and records `coupon.redeemed`.

## Languages

Text lives in `messages/en.json` and `messages/fr.json`, which must define the same keys. A test enforces this. Pip is only the avatar's look: no text calls the player Pip. Characters call them by their username, passed to a message as `{name}` from `usePlayerName()` in `components/game/player-name.tsx`, or simply say "you", and French texts don't assume the player's gender. URLs carry the language, such as `/en` and `/fr`. Players change it in the settings menu, or with the switcher on the sign-up and sign-in pages.

## Game code

Game rules live in `game/` as plain tested functions, without React or Three.js. `components/game/` displays them, and the scene loads only in the browser.

Both are grouped by domain, so that a feature's files sit together; [`docs/architecture.md`](docs/architecture.md) maps every folder, the layers and who may import whom, and where a new piece goes. `game/` has `world/`, the places, movement, clock and sky; `cards/`, the sets, boosters, binders and the shop's prices; `quests/`, with every shift in `quests/shifts/`; `log/`, the event catalogue, the browser's reports, visits and statistics; and `ui/`, pure calculations for the interface, such as moving through menus with the keys; what serves every domain, `seeded-random.ts` and `news.ts`, stays at its root. `components/game/` follows: `art/` and `scene/` draw the world, `hud/` what lies over it, `shop/`, `boosters/`, `quests/`, `shifts/` and `office/` their dialogs and games, and `game.tsx` ties them together, keeping what the game shares, such as the wallet and who the player talks to, while hooks beside the parts they serve, such as `use-game-keys.ts` for the keyboard or `quests/use-kitten-hunt.ts`, hold the rest. On the server, `player/` pays and charges, with a file per quest in `player/quests/`. A new file goes in the folder of its domain, and a domain that grows gets a folder of its own.

The world is made of paper cut-outs, seen from the side like a diorama: characters only walk left and right. The drawings are made by code on canvases in `components/game/art/`, so the repository holds no images: `core.ts` has the shared tools, such as the paper grain and the cut-out rim, and every other file draws one place with its characters, such as `dojo.ts` for Maître Kaito and his dojo. A new character or place gets its own file, or joins the file of the place it lives in. The player is Pip, a fox. `components/game/scene/paper-scene.tsx` sets up the scene and moves between places, and every place has its own file in `components/game/scene/`, beside `stage.tsx`, what they are all built from, `sky.tsx` and `outdoors.tsx`, which the outside places share, and `pip.tsx`, the player's character and the camera. The places are the bedroom, the street with our house, the shop, the Card Den, run by raccoon triplets, the bookshop, the Page Nook, which sells nothing but binders, Léa's flat in the block at the far left, Gaspard's dalgona stand, Bérénice's raffle stand, the arcade, and the bus stop at the far right. The stop's sign opens the map of the stops the bus serves, from `game/world/bus.ts`, and the bus takes the player to the other stops: Linden Park, with Papy Caillou and Lucas, and the big city, whose modern towers rise out of sight and can be seen far behind the village from the street, with smaller houses between them such as Ramen Yuzu and the dojo. Their places keep the ids `park` and `downtown`. A place's layout along its floor, the stretches where the player can do something, and its doors with where each one leads, live in `game/world/side-rooms.ts`. A door is used with the interact key, rather than by walking into it. Going from one place to another, through a door or by bus, closes two torn cardboard flats over the stage, `components/game/scene/travel-screen.tsx`, with a ticket naming where Pip is heading, Pip running, the bus driving or the administrative office's lift going up or down, and a tip. The new place is only built once the ticket is up, and the flats only open once it has drawn its first frames, so that the place left behind never shows again. Characters are never still: they breathe, and those whose eyes can be seen blink, drawn a second time with their eyes shut. Trees, reeds and tufts of grass sway in the wind, as in the art direction's prototype. Outside, the diorama stands on a table of kraft, the colour of the page behind the rooms, so that the sky never shows below its front edge: drawn in the scene, it darkens at night with the world. Talking to a character is offered in a speech bubble just above its head, placed from the top of its drawing so that it fits any size. Everything else is offered at the bottom of the screen. The sky, outside and through windows, comes from `game/world/sky.ts`; the administrative office's window shows the big city's towers over it, darkened with the evening and lit up at night like the streets outside.

The game keeps its own clock in `game/world/clock.ts`, faster than the real one: a real second is a game minute, so a day lasts 24 real minutes, with dawn, day, dusk and night. The weather holds for four game hours, drawn from the spell's number so that every page agrees: fair, cloudy, rain or storm, and snow instead of rain from December to February by the real date. Outside, the scene lays the light of the time of day over the world, warm at dawn and dusk and blue at night, and street lamps light up from dusk until dawn, their halos drawn over that light. `components/game/scene/game-clock.tsx` lets rain and snow fall in front of it, with soft lightning in a storm, left out for players who ask for less motion. The sky, the light and the lamps follow the clock minute by minute, blended between the times of day by `skyAt`, `worldTintAt` and `lampLightAt` in `game/world/sky.ts`, and a change of weather eases in over a few seconds, rain and snow building up and dying away, so that nothing changes all at once. The clock in the corner shows the game's time and weather. Every player shares the clock, moved on by their own sleeps: from eight in the evening until dawn, Pip can go to bed, and the server moves the player's clock on to seven in the morning, kept in `player_clocks`. The time and the weather are only for show: nothing that pays depends on them, and the daily quests keep following the real date.

Desktop comes first: comfort, polish and effects are designed for it. Phones must still work, with every screen usable and the game playable, but they don't need to match it, and a choice between the two goes to desktop.

The game must stay playable with the keyboard alone. Every screen puts the focus on something that can be pressed, and menus follow the movement keys through `components/game/menu-focus.ts`. While walking about, B opens the booster bag, C the binder and Escape the settings, only when no dialog, game or conversation has the keys: `use-game-keys.ts` notes whether one had them before anything else hears the press, since Escape closes a dialog on its way. `components/game/hud/controls-legend.tsx` shows the keys as keyboard keys along the bottom of the screen, for a mouse on a wide enough screen. A dialog opens through `openDialog` there, or calls `focus()` itself right after `showModal()`, never leaving the first focus to the browser or to React's `autoFocus`: browsers disagree on where an opening dialog puts it, and Safari, which doesn't count buttons as reachable from the keyboard by default, can leave it on the dialog itself. `openDialog` focuses the element marked `data-first-focus`, or else the first choice. Don't use `disabled` on a button that can have the focus, because the browser takes the focus away and no key reaches the dialog any more. Use `aria-disabled` instead.

The game was first a 3D town of Kenney models, rebuilt place by place in paper. Its code and models are gone: don't bring 3D models back without asking.

## Next.js

Read [`AGENTS.md`](AGENTS.md) before writing Next.js code. `next dev` maintains that file, so leave its block as it is.

Cache Components stays off until a feature needs it: player data must never be served from a cache.

The favicon, `app/icon.svg`, is the HUD's booster pack. The home-screen icon, `app/apple-icon.tsx`, and the picture shown when a link is shared, `app/[locale]/opengraph-image.tsx`, are generated from it and the game's own fonts by `components/brand/assets.ts`. The layout's metadata makes their links whole from `APP_URL`, which must be the public address in production for WhatsApp, Discord and the like to show the preview. `proxy.ts` leaves `apple-icon` out of the language routing, as its address has no extension.

Players learn what changed from the "What's new?" sheet, `components/game/hud/news-sheet.tsx`, which opens on arrival when there are notes the browser hasn't shown yet, and from the settings menu with every note. The notes are in `NEWS` in `game/news.ts`, their texts under `News.items` in the translations: a change players can see gets its note in the pull request that makes it, as `/open-pr` says. Notes the owner pins stay at the top, under a headline, whenever the sheet opens; the others follow by day, newest first. The browser keeps the id of the last note it showed in `localStorage`, at the owner's choice, so another device shows the recent notes again, and a first visit only shows the latest few.

The game shows its version faintly in the bottom-left corner, so that testers can say which one they play. `next.config.ts` passes the version from `package.json` as `APP_VERSION`; the release job bumps it after each merge, and its push deploys the new number.
